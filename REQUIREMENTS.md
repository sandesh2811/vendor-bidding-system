Vendor Bidding System Development Task
Mero Event | Digital Events Pvt Ltd
Project
Build a vendor bidding and booking system for Mero Event. The system should have two portals: an internal Mero Event vendor management portal and a portal for vendors. Design the workflow, database, interface and implementation yourself based on the requirements below.
Mero Event vendor management portal
• Add and manage vendors.
• Create a simple event quotation or work request, including event details, items and the option to upload reference photos.
• Send the request to one specific vendor or to multiple vendors for bidding.
• View the prices and responses submitted by vendors, compare the bids and identify the best option. Mero Event should make the final vendor selection.
• Once a quotation becomes a booking, record the booking amount, amount paid and pending amount. Show the vendor payment details for that booking as well.
Vendor portal
• Vendors can log in and see requests sent to them.
• Vendors can review the work details and photos, then submit their price or quotation.
• Vendors can see the status of their own submissions and bookings. Each vendor should only have access to its own information.
Technology
Use TypeScript and Next.js for the frontend. For the backend, use NestJS or Supabase. Use PostgreSQL as the database. You may choose supporting libraries and services as needed.
Submission and presentation
Submit your source code and instructions for running the project. You may deploy the system online or run it locally. On the scheduled interview date, present the working system, demonstrate both portals and explain your design and technical decisions. No deployment is required if the local version can be demonstrated.
Future scope
As part of your presentation, propose features or improvements you would add in a future version of this system. Explain how they would help Mero Event and which ones you would prioritize. You do not need to build these additions for this task.
